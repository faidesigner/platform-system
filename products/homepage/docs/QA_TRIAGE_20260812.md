## 2. 구조적 문제 (요청 범위 밖이지만 지금 안 잡으면 계속 재발)

1. **PRD 배포가 파이프라인에서 끊겨 있다.** CLAUDE.md에 "develop 머지 ≠ dev 배포" 규칙은 있는데, 그다음 칸인 **"dev 검증 ≠ PRD 배포"**가 비어 있다. 그 결과 HOM-60/61/62 3건이 "고쳤는데 또 올라온" 유령 티켓이 됐다. 실제 손실: QA 재작성 3건 + 개발자 재조사.
   → 규칙 추가 + `version.json` 대조를 QA 착수 체크리스트에 PRD까지 확장.

2. **죽은 중복 컴포넌트** `packages/ui/components/Footer.tsx`. `index.ts`가 export하는 건 `components/footer/Footer.tsx`인데, 루트의 레거시 파일은 남아서 **옛 주소 `0662`와 CCTV 링크를 그대로 들고 있다.** grep하면 이게 먼저 걸려 오진을 유발한다(이번 조사에서 실제로 걸렸다). 루트의 `Header.tsx`·`NavigationBar.tsx`도 같은 의심 대상 → 일괄 점검 후 삭제.

3. **CUSTOMER_IMAGES 배열이 두 군데 중복** (`app/[locale]/page.tsx`, `components/sections/home/CustomersSection.tsx`). HOM-69 같은 이미지 교체 시 한쪽만 고치면 조용히 어긋난다. → 단일 소스로 통합.

4. **`ProductHero.tsx`의 `FALLBACK_VIDEO`가 `w3schools.com`의 외부 데모 mp4.** 운영 코드가 외부 사이트 리소스를 참조한다. `MISSING_FROM_DESIGN` 값도 config에 다수 남아 있다. → 즉시 제거 대상.

5. **로케일 분기 정책이 코드에 흩어질 참이다.** C그룹 6건이 전부 "특정 로케일에서만 노출/링크 변경". 컴포넌트마다 조건문을 넣으면 다음 요청에서 무너진다. → 선언적 단일 지점을 먼저 만들고 6건을 그 위에 얹는다.

6. **머지 완료된 워크트리 6개 방치.** 전부 `git branch --merged develop`에 잡힌다. → 정리.
