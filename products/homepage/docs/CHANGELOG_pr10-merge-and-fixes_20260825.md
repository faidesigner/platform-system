### 4-4. footer cctv 키 잠복 회귀 (HOM-61)

`footer.policies.cctv` 키가 "맞춤형 광고 설정" 값을 담고 있었다 — HOM-61에서 제거한 영상정보처리기기 방침 슬롯 재활용이라 키명과 내용이 어긋난다.

더 위험한 건 폴백이었다.

```ts
{ label: l.cctv, href: cookieHref ?? POLICY_HREFS.cctv }  // '/document/cctv-policy.pdf'
```

`cookieHref`가 주입되지 않으면 **제거한 CCTV 방침 링크가 조용히 되살아난다.** 파일이 `public/document/cctv-policy.pdf`에 아직 존재하므로 404도 아니다. `FooterBridge.test.tsx`의 HOM-61 가드가 innerHTML에 "cctv"가 없음을 확인하고 있어 현재는 잡히지만, 그건 주입값이 있을 때 얘기다.

→ 키명을 `adSettings`로 정리하고 **폴백 상수 자체를 삭제**했다. `cookieHref`가 없으면 폴백이 아니라 해당 행을 렌더하지 않는다. 갈 곳 없는 항목을 띄우는 것보다 안전하다.

### PRD 배포 시 주의

`scripts/deploy.sh`는 체크아웃된 브랜치가 아니라 **현재 워킹트리**를 빌드한다. `version.json`의 sha가 main과 일치하려면 `develop → main` 머지 후 **main 워크트리에서** 실행해야 한다. 로컬 main 워크트리는 `origin/main`보다 175커밋 뒤처져 있어 `git pull`이 선행 필요하다.

`develop`과 `origin/main`은 그래프상 갈라져 있지만(main 단독 3커밋) **내용은 develop이 상위집합**이다 — main 단독 파일 0건, Meta 도메인 인증 태그·랜딩 폼 하드닝·ja 우편번호 모두 develop에 존재. 머지로 유실되는 것은 없다.
